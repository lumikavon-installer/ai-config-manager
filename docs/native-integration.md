# Native desktop integration and release gates

The Tauri 2 shell is real native integration, not browser mocks. Its production frontend is the local `dist` bundle. Browser preview intentionally cannot prove credential-vault, tray, startup or installer behavior.

## Implemented behavior

- `config_read`, `config_save`, `config_check`, `config_test` and `history_list` call the shared Rust core on blocking workers. Keychain prompts, disk operations and the explicit `/models` request do not block the webview event thread. No API returns a decrypted credential to JavaScript.
- One hidden `main` window is created, then shown after preferences and tray initialization unless silent mode is safe. Default language is Chinese; preferences are `silent_start: true`, `close_to_tray: true`. On first run the app attempts to register current-user launch-at-login once (`autostart_default_applied`); a failed attempt is surfaced and retried on the next launch, while a later user choice to disable it is preserved. The installed product name is `AI配置管理器`; the executable remains `ai-config-manager` through `mainBinaryName`. The window title and tray tooltip follow the saved language (`AI配置管理器` / `AI Config Manager`).
- A local agent listener runs for the lifetime of the process. Unix uses a Unix domain socket; Windows uses AF_UNIX through `uds_windows`. The socket normally lives at `~/.config/ai-config-manager/agent.sock` (a deterministic per-user temp subdirectory is used if that path exceeds the AF_UNIX limit), is 0600 on Unix, and is accompanied by a 0600/protected-DACL random token file. Every request carries the token; the listener handles `ping`, `read`, `check`, `history`, `test` and `save` through the shared `Store`, plus an HTTP/1.1 REST protocol on the same socket. REST endpoints expose `GET /ai-config`, `GET /sync`, `POST /sync/settings`, `POST /sync/items`, `PATCH|DELETE /sync/items/{id}` and `POST /sync/run`; they require `Authorization: Bearer <agent.token>`. A JSON save uses source `skill` and emits `config-changed`; the UI reloads a clean editor and marks a dirty one as externally conflicted. A second listener is refused rather than displacing the live one. Stale socket/token files are removed on exit and reclaimed on the next launch.
- GitHub and custom Git sync share Argon2id + AES-256-GCM snapshots and per-item timestamp merging. Remote winners apply only to registered, enabled local files/applications through revision/digest checks. `sync.json` holds repository metadata, items, policy, deadlines, status and at most 100 records; GitHub token and encryption password stay in the OS credential vault. Custom Git uses installed Git with the current user's credential helper / SSH agent. Its temporary bare repository preserves other branch files and uses a branch lease for writes. The explicit repository test reads/fetches, creates and deletes a unique probe branch, and reports cleanup failures without changing the sync branch or settings. A successful probe verifies general write access; protected-branch rules still apply to actual sync. Offline third-party applications are deferred (`SYNC_APPLICATION_OFFLINE`) instead of failing the attempt, so the remaining items still sync; deferred items and transient network/Git failures schedule a backing-off retry capped at the configured interval.
- Preferences reside at Tauri's platform app-config directory (`dev.aiconfig.manager/settings.json`), separate from provider YAML. Schema version 1 is validated. Missing preferences use defaults. Malformed, unsupported or unreadable preferences generate a visible warning and remain untouched until an explicit preferences save. Saves write a temporary file in the same directory, fsync it, atomically replace the destination, and fsync the directory on Unix. Unix preference files are 0600. If replacement succeeds but directory synchronization fails, the new values become active in memory and the returned view includes `SETTINGS_DURABILITY_UNCERTAIN`; the application does not pretend the replacement rolled back or automatically repeat it. Preferences contain no credentials. External editing of preferences while the app is running is not supported: `settings_read` returns the current in-process state; restart to load external edits.
- The localized tray offers Show, Hide, Settings and Quit. Settings restores the window and emits `navigate` with string payload `settings`. Language changes rebuild the native menu. Quit calls `app.exit(0)` rather than hiding the window.
- Closing hides only when the preference is enabled and a usable tray is known. Hide requests fail with `TRAY_UNAVAILABLE` otherwise. `--silent` or stored silent mode hides only after successful tray creation. Initialization warnings always force the window visible.
- Linux additionally requires a session-bus StatusNotifierWatcher reporting `IsStatusNotifierHostRegistered=true`. This deliberately falls back to a visible window on desktops without a verified tray host, including GNOME sessions without a suitable extension. A tray object alone is not treated as proof of a usable Linux tray.
- The official single-instance plugin is registered first. A second launch restores and focuses the existing main window instead of starting another editor.
- Autostart uses the official Tauri plugin, with `--silent`. Windows uses OS login registration; macOS explicitly selects LaunchAgent; Linux uses the plugin's desktop autostart mechanism. Reading settings queries actual OS registration; there is no local boolean pretending to be registration. Failed queries return `autostart_known: false` and an `AUTOSTART_UNKNOWN` warning, so the UI must display Unknown rather than Disabled. Enable/disable commands query the OS again and fail on mismatch. Autostart is not enabled automatically.
- IPC is allowed only for the local main window's declared application commands and event listen/unlisten. No generic filesystem, shell, process, remote-origin, or plugin-autostart JavaScript permissions are granted. Native code owns the narrowly scoped startup and Git operations. Production CSP disallows external scripts, remote API connections, frames, objects and forms. The only model-provider request is the explicit, user-triggered `config_test`/`test` `GET {base_url}/models`; it does not follow redirects or return the response body. Local agent IPC is Native-only and is not exposed to the webview.

## Build requirements

Rust 1.90+; Node/npm as pinned by project configuration; Tauri platform prerequisites from https://v2.tauri.app/start/prerequisites/. Build on each release platform, not only via cross-platform Rust checking. Linux requires GTK/WebKitGTK/appindicator development dependencies and the Secret Service stack. Windows needs the appropriate Microsoft build tools and WebView2. macOS builds require Xcode command-line tools and signing/notarization for distribution.

`cargo check --target ...` proves type checking only. It does not prove that a desktop tray appears, an installer works, a keychain authorization prompt succeeds, or an OS login entry actually starts the installed binary. Do not describe these as passed without recording native evidence.

## Required native acceptance gates (not claimed as tested by source generation)

Run on installed packaged builds on Windows, macOS and a supported Linux desktop, using a disposable OS account/profile and test-only credentials:

1. Fresh launch shows Chinese UI and the `AI配置管理器` window title; the left navigation has no duplicate icon/brand/subtitle; switching language updates UI, native tray and window title/tooltip immediately and survives restart. On a clean profile, silent start is enabled and the first launch registers launch-at-login; a later user disable is not overridden. Malformed settings force a visible warning, preserve original bytes and recover after explicit save.
2. The Windows NSIS installer shows the language selector (简体中文/English), installs with the Chinese display name by default, and launches an executable named `ai-config-manager.exe`. Uninstall uses the same display name. Installer and uninstaller icons show the `A` mark.
3. With the app running, `ai-config status` reports `running: true`, `read`/`set` route through the agent, and a skill/CLI save updates a clean GUI automatically while a dirty GUI is marked conflicted. Stop the app: `status` reports `running: false`, and `read`/`set` operate on the file directly. Corrupt the token or send a wrong token while the socket is live and verify `AGENT_TOKEN`/`UNAUTHORIZED` without a fallback save; a missing token is treated as unavailable before any request is written.
4. `ai-config test` and the GUI test button perform `GET {base_url}/models` only on explicit action, classify 200/401/404/5xx/redirect/timeout without returning the body, and never run automatically on save or startup.
5. Using the same socket with `curl --unix-socket` and the token header, verify `GET /ai-config`, `GET /sync`, `POST /sync/items`, `DELETE /sync/items/{id}` and `POST /sync/run`. Requests without the token return HTTP 401; JSON-RPC CLI requests still work on the same socket.
6. Configure a disposable GitHub repository/token/encryption password, register one extra config file, run sync, and verify the remote `.ai-config-manager/sync.enc` is encrypted, the list/status shows success with time/remote URL, and no token/password appears in `sync.json`, logs or responses. Test 401/403/404/409/network and busy paths without printing response bodies or secrets.
7. With the tray present, normal launch is visible; stored silent mode and `--silent` are hidden. Show restores and focuses; Settings opens the settings panel; Hide hides; Quit removes the process. Close-to-tray off exits when the only window is closed. A second process launch reveals the first instance.
8. Without a Linux tray host (and under injected tray-creation failure on other platforms), silent launch remains visible, hide is refused, close is not intercepted, and a diagnostic is displayed. Also test tray-host disappearance after startup: host-loss recovery is not currently monitored and is a known limitation.
9. Toggle login startup on, verify the actual OS entry targets the installed binary with `--silent`, sign out/in or reboot, verify one hidden instance with an accessible tray. Toggle off, verify the entry is removed and next login does not launch. macOS test must inspect the LaunchAgent. Permission denial and unsupported session must be surfaced without a false success state.
10. Save a disposable API key, restart, validate decryptability through the native core; inspect YAML/history/diagnostics for no plaintext. Deny or lock the OS keychain, and verify errors without exposing values. Try concurrent GUI/CLI updates and a stale revision conflict.
11. Build/install/uninstall all intended installer formats; check icons, high DPI, keyboard navigation, signing and platform-specific packaging. No production signing credentials are included.
12. Exercise remote navigation and malformed IPC attempts: only the shipped local main webview may invoke the documented commands, and arbitrary shell/filesystem operations must remain unavailable.
13. Verify Sync list, Applications and Sync records as separate sidebar pages, with target and automation under settings. Test a disposable GitHub and custom SSH/HTTPS repository: read-only access must fail write testing; permitted access must remove its probe branch; a server rule denying deletion must display the residual ref. Check system Git discovery and credential helper/SSH agent behavior from the installed desktop process. A protected sync branch can still reject actual sync after a general permission test.

The automated settings tests cover missing-file defaults, persistence round-trip, malformed-file preservation, unknown schema handling and invalid-language rejection, unknown-field rejection, failed-save state preservation, and injected post-replacement directory-sync failure with matching disk/cache state and a durability warning. Run `cargo test --manifest-path src-tauri/settings-tests/Cargo.toml` to execute the production preferences module without GUI dependencies. Core tests provide separate evidence for storage and encryption. Automated test completion is recorded by the top-level verification report, not inferred here.
