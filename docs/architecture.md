# 产品范围、架构与验收故事

本项目只管理当前用户的 AI 接口配置（OpenAI 兼容对话、向量、Laya 决策与 CosyVoice 语音）；不提供模型网关，不会在保存、启动或阅读历史时调用上游 API。只有用户显式点击“测试 AI 连接”或运行 `ai-config test` 时，才会携带已保存密钥（空密钥不带授权头）请求配置的 `{base_url}/models`，且不读取响应正文、不跟随重定向。桌面用户与同一系统用户的受信任本地程序是使用者；不能防御已控制该用户会话的恶意程序。

## 信息架构与流程

配置页 → 读取脱敏视图 → 编辑 URL/模型/新密钥 → 校验 → 乐观版本检查 → 保存 → 成功后刷新视图及历史。侧边栏另有历史记录、同步列表、应用注册、同步记录和设置。设置页按常规、同步目标、自动化、关于四个 Tab 展示；同步管理区域保留跨页草稿。

配置文件、锁文件、非敏感恢复日志和历史由核心库统一处理；前端不得读文件或接触已保存密钥。Tauri 命令只承接类型化请求，通过阻塞任务池调用核心。CLI/Skill 与 GUI 复用同一核心，不再实现第二套 YAML/加密逻辑。

## 层次

- React/TypeScript：表单、加载/错误/成功状态、国际化与无障碍交互。
- Tauri 2：IPC、窗口、托盘、自启动、应用设置、同步设置与状态界面。
- ai-config-core：校验、YAML 保留、并发控制、持久化与恢复、加密、安全存储、历史、本地代理 JSON/REST、显式连接测试与 GitHub 同步加密。
- ai-config CLI + Skill：脱敏读取、校验、历史、连接测试与字段修改，明确失败码；应用运行时经本地 AF_UNIX socket 读取/写入，否则直接使用同一核心；受信任 Rust 集成使用内存中配置，不输出凭据。

## 顺序故事与完成条件

1. 基础与边界：独立 workspace、类型化 IPC、默认配置路径；构建验证。
2. 配置持久化：新增/编辑/保留未知字段、原子替换、并发冲突拒绝；临时目录集成测试。
3. 安全密钥：AES-GCM 随机 nonce、系统安全存储、失效密钥失败关闭；模拟 vault 的正反测试，原生安全存储另行验收。
4. 历史：成功提交后记录、最多十条、脱敏 diff、稳定规范化摘要、崩溃恢复；故障注入与持久化测试。
5. 交互：六个侧栏页面、四个设置 Tab、空/加载/错误/成功/未解密状态、危险降级确认；组件测试及生产构建。
6. 桌面系统：托盘、真正退出、静默启动恢复、系统实际自启动；编译加各 OS 手工验收，不以模拟代替原生验证。
7. Skill 与本地代理：与核心一致的错误和读写语义，应用优先、文件回退，默认无秘密输出；CLI、JSON socket 与 HTTP REST 集成测试。
8. 配置同步：GitHub 与自定义 Git 目标、真实仓库读写探测、文件与应用回调注册、定时同步、实际结果与自动保留记录；Argon2id + AES-GCM 加密传输，按配置更新时间合并及写回已注册目标；秘密只进系统凭据存储或系统 Git 认证设施。
9. 发布：锁定依赖、完整 README、清洁构建与逐项复核，明确未验证的原生运行门槛。

每个故事异常包括无权限、文件损坏、依赖/安全存储不可用、重复操作和取消。任何不能证明通过的验收记录为未验证，而非成功。
